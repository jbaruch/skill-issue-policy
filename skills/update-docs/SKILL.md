# Update documentation

Edit the requested documentation, then check formatting, links, examples and
accuracy. A new quickstart section is still documentation work. Do not invoke
code-review polling solely because the request is called a ticket.

Follow the consuming repository's contribution policy and the user's requested
scope for branching, committing and PRs. Documentation is not an automatic
exception to branch protection. If asked only to edit, finish after validation.
For application behavior changes, use `fix-the-ticket` instead.
